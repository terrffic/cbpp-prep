## 2. P0-1 12 道错答：根因与算法修复

**根因**：生成器先 `rot(opts, i % 4)` 旋转选项数组，之后仍用 `a = i % 4` 当答案索引——转完没重算索引，正确答案被移到别处，索引还指着旧位置。

**修复**（不是改字母，是换写法）：

```js
function pick4(correct, pool, k){
  const uniq = [];
  for (const x of pool){ if (x !== correct && uniq.indexOf(x) < 0) uniq.push(x); if (uniq.length === 3) break; }
  let pad = 1;
  while (uniq.length < 3 && pad < 60){ const c = (typeof correct === 'number') ? correct + pad*7 : correct + ' #' + pad;
    if (c !== correct && uniq.indexOf(c) < 0) uniq.push(c); pad++; }
  const arr = uniq.slice(0,3);
  const a = ((k % 4) + 4) % 4;
  arr.splice(a, 0, correct);          // 正确项显式落到第 k 位
  return { o: arr, a: a };            // 选项与索引同时产出，结构上不可能再错位
}
```

四处生成器（DPMO / PCE / FPY / DMAIC）全部改用 `pick4`。同时把 DPMO 的干扰项从 `v*3+1`、`v*4+2` 这类凑数值，换成**可解释的计算错误**：忘记除机会数（`v*op`）、数量级错（`v*10`、`v/10`）、近似算错（`v/2`、`v*2`）。

**验证方式**：`tools/audit.js` 内置 24 道计算题的**独立复算**（不复用页面里的公式，用审计脚本自己的算式重算并与答案比对），结果 24/24 通过。例如 `g5-dpmo1`：90÷5000=0.018 → ÷6=0.003 → ×10⁶=**3,000**（此前该题答案为 30,000）。

| 题号 | 修复前 | 修复后 |
|---|---|---|
| g5-dpmo1 | 30,000 | 3,000 |
| g5-dpmo3 | 20,000 | 2,000 |
| g5-dpmo5 | 25,000 | 2,500 |
| g5-dpmo7 | 20,000 | 2,000 |
| g5-pce1 | 12.5% | 25% |
| g5-pce3 | 2% | 4% |
| g5-pce5 | 3% | 6% |
| g5-fpy1 | 30% | 70% |
| g5-fpy3 | 5% | 95% |
| g6-dmaic1 / 3 / 5 | 阶段标签错位 | 正确阶段 |

## 3. P0-2 全库复核（323 题）

**方法**：先自动校验（结构 / 中英 / 计算 / 风险词），再**逐题人工通读**：按域导出「题干 + 4 选项 + 正确项 + 解析」，九个知识域全部读完，逐题判定唯一最佳答案、干扰项是否有业务逻辑、题干是否足以定解、是否存在多解。

**结论分布**（`reports/ledger.csv`，15 列，323 行）：

| 结论 | 含义 | 数量 |
|---|---|---|
| A | 保留 | 255 |
| B | 优化（改解析/换干扰项，答案不变） | 49 |
| C | 实质错误，修订后复核 | 13 |
| D | 题干/解析不一致、绝对化或无依据，重写 | 6 |
| E | 超纲/重复/无法解决歧义，移出 | 0 |

问题类型分布：解析为通用模板 29、干扰项质量不足或无依据比例 20、答案错位 12、题干与解析不一致/绝对化 6、选项包含关系致一题两解 1。

**本轮人工复核新发现并修掉的问题**（自动校验没抓到、或抓不全的）：

1. **`x2-1` 题干与答案矛盾**：题干写"根据金额可能进入**一条或多条**后续路径"，指向 OR 语义，答案却是 XOR。→ 题干改为"按金额**只能进入其中一条**对应的审批路径"（中英同步）。
2. **`g2-gw6` 一题两解**：正确项是"并行网关（AND）＋多实例会签"，干扰项里却有"并行网关（AND）"——后者是前者的子集。→ 生成器加约束：`d[2].indexOf(p[0]) < 0`，正确答案的子集不得作为干扰项。
3. **`ch7-1` 与 `ch8-2` 权责口径打架**：ch7-1 说流程所有者"拥有变更批准权"，ch8-2 说跨域变更由治理委员会批准。→ ch7-1 解析改为"流程本身的变更由所有者批准；跨流程政策/标准/优先级冲突升级治理委员会裁定"，与 ch8-2 形成一条边界而不是两个互相打脸的结论。
4. **`ch7-4` 残留"失败率高（约 70%）"**：上一轮只修了英文条目，中文题干仍是旧版。→ 改为"BPR 项目失败后做复盘时，最常被归因的原因"，解析明确"这是定性结论，不代表某个固定失败比例"。
5. **`ch2-3` 与第 7 章边界**：模型变更批准责任补一句"涉及跨流程治理决策时由治理委员会裁定"。
6. **30 道生成题解析是"八题共用一段话"**（`g1-cls` / `g2-gw` / `g3-tool` / `g4-pr`）：这类解析回答不了"为什么不是那个"。→ 改为**逐题识别词式解析**：先说本题的识别信号，再点名最易误选项并说明差异，中英同步。

**没做到的**：E 类没有把任何题移出正式题库——目前 323 题全部留在卷池。是否应该更激进地砍掉一部分（例如选项长度差异过大的题，见 G-2），我选择"先记录、不擅自删题"，因为这属于内容取舍，需要你确认口径。

| 指标 | 实测 |
|---|---|
| 每套题量 / 域分布 | 140，9/17/14/15/15/14/17/19/20（五套相同） |

| 两两重合 | 39%–49%（最低 P1-P3 39%，最高 P1-P5 49%） |

| 分章练习与模考重合 | 36 / 36（分章练习取自同一题库） |

**结构性下限**：每题等概率从 323 题抽 140 题，两卷期望重合 140²/323 ≈ 61 题 ≈ 43%。也就是说 **39%–49% 已接近数学下限**，只要不把题库扩到 700 题左右，五套就不可能真正独立。第 9 域池子 21 题、单卷要 20 题，域内几乎必然重合。

**处理**（不降质量、也不虚称独立）：

1. 组卷加**跨卷轮转起点**（`off = (n-1)*need mod pool`），把两两重合从最高 54% 压到 49%，独立题从 295 提到 299。
2. 界面标注：第 1、2 套为「基准卷」，第 3–5 套为「**强化练习卷** · 与第 1 套重合 X%」，X 由页面运行时真实计算，不是写死的文案。
3. README、组卷说明、报告三处口径一致：五套**不是**互相独立的测评。
